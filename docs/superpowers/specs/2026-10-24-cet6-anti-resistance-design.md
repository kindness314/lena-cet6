# 六级「低抵触」学习工具 · 设计

日期：2026-10-24 ｜ 目标考试：2026-12-12 15:00–17:25（六级笔试）｜ 剩余 49 天

## 1. 意图与为什么

用户讨厌英语、懒得背单词，现有背单词 App 连打开都不愿意，但六级必须考好（425 分通过线）。
日常零阻力行为是**刷群聊**和**读小说**，且主要在手机上（Xiaomi 17 Pro / Android）。

所以这个工具不是"更好的背单词 App"，而是：**把每天必做的英语最小动作，塞进一个看起来像聊天/阅读界面的壳里**，把启动成本降到接近零。

成功标准（用户视角）：
- 每天不需要"下定决心"就能完成 90 秒以内的英语动作。
- 49 天内高频词有稳定曝光，阅读时能点词查义、自动认出六级词。
- 断更不产生负罪感，回来即继续。

## 2. 目标 / 非目标

**目标**
1. 默认首屏是「聊天」：每天 5 条英文消息（单词/短句），回复即完成，不显示进度条与分数。
2. 「阅读」：内置文章 + 用户自己贴入/导入英文文本，点任意词出中文，六级词自动高亮。
3. 「目标」：多考试倒计时（六级 + 其他考试），每日最低任务，一键完成。
4. 第二天打开无需重新加载（PWA 离线可用），数据只存本机。
5. 诚实的能力边界：只覆盖"词汇 + 阅读输入"，不覆盖听力/作文/翻译。

**非目标**
- 不做账号、云同步、社交、排行榜、付费。
- 不堆 5500 全词库；只做高频核心词（按语料词频排序）。
- 不做 AI 生成内容、不生成假例句。
- 不做真题听力/写作训练（无合法离线音源与题源；正文导入可由用户自行完成）。
- 不做惩罚性机制：没有红色断签、没有扣分、没有"今日未完成"弹窗。

**反目标（做成这样就失败）**
- 一打开就是"今日任务 0/50"的压力界面。
- 每次要 20 分钟以上。
- 需要注册/联网/PC 常开才能用。

## 3. 约束与已定决策

| 项 | 决策 | 理由 |
|---|---|---|
| 平台 | 纯静态 PWA（Vite + TypeScript，无框架） | 手机浏览器即可用，可装桌面；无后端 |
| 数据 | localStorage，支持导出/导入 JSON | 换机/清缓存可恢复；隐私 |
| 部署 | 构建产物为纯静态；开发/自用走局域网 + HTTPS（mkcert）以便安装与离线 | 正式公网托管需用户授权后再做 |
| 词库（复习） | ECDICT（MIT）`tag` 含 `cet6` 的子集，按 `bnc`/`frq` 词频取核心 ~800 | 有中文释义、词频、音标、词性 |
| 词库（查词） | 另一份 ECDICT 子集：cet4/cet6/ky 标签 + 词频前 4 万，约 4–6 MB | 阅读中点词才不至于大量「未收录」；不参与 SRS |
| 例句 | Tatoeba 英中句对（CC BY 2.0 FR），每词 1–2 句；缺例句的词用「单词 + 释义卡」，不剔除、不编造句 | 真实语境，可署名 |
| 文章 | Simple English Wikipedia（CC BY-SA）+ 公版短文，构建期抓取为静态 JSON | 合法可分发；可离线 |
| 发音 | Web Speech API（系统 TTS） | 零依赖；不出声时静默降级为不发音（不伪造） |
| 复习 | 简化 SM-2：10 分钟 / 1 / 2 / 4 / 7 / 15 天 | 够用，代码可维护 |

## 4. 交互设计

### 4.1 聊天（默认页）
- 界面复刻 IM 会话列表 → 点进单个联系人（如「Lena」）。
- 每天第一条进入时，生成 12 条待回消息（默认值，用户可选 5/8/12）；每条 = 一句含目标词的英文 + 4 个中文选项。
- 选对：气泡变淡并显示一句中文释义；选错：直接显示正确答案 + 释义，无惩罚文案。答错词在 3 条消息后重现。
- 回完 12 条出现「再来 5 条」（可选）与「去阅读」（可选）。没有"明天再来"的门锁。
- 未读红点 = 待回消息数；断更后不出现任何红字；断更不补发，当天按新一天生成。
- 消息顺序：先到期复习词，再新词；单日新词 ≤ 8，总额度 12 条，复习吃掉额度时新词顺延。
- 选项：4 个、同词性，排除中文释义高重合的近义项；一条消息只承载 1 个目标词。

### 4.2 阅读
- 文章列表（内置 10–15 篇，按词频难度排序）。
- 阅读页：段落排版，六级词虚线下划；点词弹释义卡（音标/词性/中文/例句）。
- 词形：用 ECDICT `exchange` 建「词形→原形」映射；`studies/running/harder/don't` 等还原后命中，高亮展示原词形，卡片按原形释义。
- 卡片只有两个动作：「发音」「加入复习」（进入 SRS，之后出现在聊天里）。不设独立生词本页面。
- 「导入」：粘贴任意英文文本或选 txt 文件 → 自动标注 → 可读、可点词。
- 读完不要求做题，不记录"阅读时长"。

### 4.3 目标
- 倒计时卡片：六级 2026-12-12 15:00；可添加其他考试（名称+日期）。
- 每日最低任务只显示一句："回 5 条消息"；完成即打勾，不显示连续天数。

## 5. 数据模型（localStorage 单键 `cet6.state.v1`）

```
{ words: { [id]: { box, due, seen, wrong } },
  chat: { lastDay, pending: Msg[], answeredToday },
  reads: { [articleId]: { openedAt } },
  goals: [{ id, name, date }],
  settings: { dailyNew, dailyReview, sound } }
```
每日消息在本地按日期生成（同一日期结果稳定），不需要服务器。

## 6. 验收

1. `npm run dev -- --host` 后手机同网段打开，完成 5 条消息 ≤ 90 秒。
2. 断网后再次打开（已安装/已缓存）可正常使用。
3. 点词 100% 出释义（词表内）；句中标出的目标词与词库一致。
4. 倒计时显示到 12-12 15:00 的天/时，跨零点正确。
5. 清缓存前可导出 JSON，导入后复习进度还原。
6. 移动端 390–430px 宽度无横向滚动；暗色模式可用。

## 7. 留给实现者的决定

- 是否需要聊天列表页（多联系人）还是单会话直达；倾向直达以减少一次点击。
- 文章抓取的具体条目与数量；抓取脚本失败时的处理（构建期报错，不静默）。
- 自托管 HTTPS 的具体端口与证书分发说明（写进 README）。
- 词表截断阈值（默认取词频前 800，可配置）。

## 8. 交付步骤

1. 构建脚本：下载 ECDICT → 生成 `public/data/words.json`；Tatoeba → `sentences.json`；文章 → `articles.json`。
2. 应用骨架：Vite + TS，路由（chat / read / goals）。
3. 聊天引擎 + SRS。
4. 阅读器 + 点词卡。
5. 目标页 + 导出导入。
6. 离线缓存 + 安装清单。
7. 本地验收 + 手机实测。
